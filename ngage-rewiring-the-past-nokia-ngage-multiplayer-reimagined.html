Rewiring the past: Nokia N-Gage multiplayer reimagined

Some projects are too interesting to leave unfinished.

Back in 2023, I started working on something I always thought would be a pretty cool idea:

Bring online multiplayer back to the Nokia N-Gage.

Remember the N-Gage? Nokia's gaming phone from the early 2000s. Some of its games supported multiplayer, but only locally over Bluetooth.

The idea was simple: What if we could make those games think they're still playing over Bluetooth, while actually connecting players over the Internet?

I got started, but eventually hit a wall. The original GameComms SDK was poorly documented, and reverse-engineering its behavior turned out to be a much bigger challenge than expected.

So the project went dormant.

Fast forward to 2026. I handed the repository over to Claude with one goal: Make it work.

And that's how PhantomLink came back to life.

The interesting part isn't just getting AI to write code. It's tackling a pretty unusual engineering problem.

Here's how it works:

  1. Replacement DLL: PhantomLink replaces the original GAMECOMMS.DLL that N-Gage games use for multiplayer. The goal is to keep the original games completely unmodified.
  2. Bluetooth bridge: The N-Gage still communicates over its native Bluetooth interface. An ESP32 or a PC (including a Raspberry Pi) acts as a bridge.
  3. Internet transport: The bridge forwards the GameComms traffic over TCP to a central server.
  4. Matchmaking & routing: The server groups players by game and API version, manages sessions and player slots, and forwards multiplayer data between devices.

The really nice thing is the separation of responsibilities: the replacement DLL preserves the original GameComms behavior, the bridge handles transport, and the server handles sessions and routing. The server doesn't need to understand the game itself.

And then there's the compatibility challenge.

The original N-Gage SDK had multiple GameComms API variants. PhantomLink now provides 11 DLL variants, dealing with the original Symbian ABI, exported functions, callback behavior and binary compatibility.

The implementation is split into portable C engines, platform-specific adapters, a shared protocol library and automated tests. Even the core state machines are designed to run without threads or blocking calls, making them testable without the original hardware.

It's a great example of taking an old, proprietary ecosystem and building a modern infrastructure around it without changing the software that runs on it.

There's still real-hardware validation to do, but the protocol, server, bridge and DLL logic are implemented, with automated test coverage.

And honestly, there's something quite satisfying about the idea that two people can now potentially play an early-2000s N-Gage multiplayer game from opposite sides of the world.

A dormant project, a rather unusual engineering challenge, and a little help from Claude.

The N-Gage deserves another life.
